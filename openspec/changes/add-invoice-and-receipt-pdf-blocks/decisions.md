## Goals

- Give the Invoice and Receipt PDFs one shared, reviewable implementation in
  `@grade10/ui` — the pdf-lib renderer `grade10` already built and ships in
  production, superseding both this repository's DOM sketch-turned-component
  and the fact that `grade10` had to build its own copy at all (Q18).
- Carry every line the pdf-lib renderer already draws, as data the caller
  supplies — no new content, no new requirement.
- Route every label the renderer draws through a `copy` argument, matching
  the no-i18n-in-`@grade10/ui` rule every other block already follows (Q20).

## Non-Goals

- Defining the tax line's rate, regime or shape, or reserving a slot for
  either it or a formal tax receipt's company/tax-ID block. Retired with the
  DOM contract (Q19) — nothing in production ever exercised either slot, and
  a future change reserves one again if a real requirement resurfaces.
- Carrying the bank rails section, the manually-settled mark, or Superseded
  invoice. Retired with the DOM contract for the same reason (Q19).
- Wiring `grade10`'s consumers onto the moved renderer's exact import path.
  That is `grade10`'s task, named in this change's impact but not built here
  — the renderer itself, and the data it already takes, do not change shape
  by moving.
- Resolving the invoice/receipt ID format disagreement
  (`docs/references/auction-invoice-and-receipt-contents.md#open-questions`).
  Out of scope, as it is everywhere else that has touched these documents.
- Changing anything `winner-order/spec.md` already requires about either
  document's content, controls or visibility.
