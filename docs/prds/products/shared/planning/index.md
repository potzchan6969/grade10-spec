Planning is not a product surface. It is the set of rails that carry a change
from a product idea to a released feature across this store and the
application repository: the schema every change is written on, the board that
reads where each change stands, and the messages that tell the next teammate
it is their turn.

## Mechanism

A change is a directory of files, and every fact the rails show is read from
those files on `main`: the stage from which artifacts exist, the progress from
ticked boxes, the hands from one record in the change's manifest. Nothing is
set by hand, so nothing goes stale when nobody updates it.

## Users

Product managers, designers, QA and engineers, because each has a hand on
every change; and whoever cuts a release, because the same files say what is
ready.
